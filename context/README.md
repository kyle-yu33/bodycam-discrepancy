# EvidenceLens — Project Context

This folder is the team’s concise source of truth for the Hack the Hill project. It consolidates the decisions, research, scope, architecture, safety boundaries, and demo direction agreed so far.

## Start here

- **[main.md](main.md)** — canonical project brief: problem, solution, differentiation, scope, and current decisions.
- **[mvp.md](mvp.md)** — exactly what must be built for the hackathon demo.
- **[stack.md](stack.md)** — recommended technical stack and why it is deliberately small.
- **[skeleton.md](skeleton.md)** — application skeleton and build order.

## Non-negotiable product principle

> **No claim without a source. No source without a timestamp. No certainty when footage is unclear.**

## How to use this folder

1. Read `main.md` before changing the product scope.
2. Read `mvp.md`, `stack.md`, and `skeleton.md` before building.
3. Treat `safety.md` and `positioning.md` as guardrails for copy, UI labels, pitch claims, and judge questions.
4. If a build decision changes the product claim, update `decisions.md` and the relevant document immediately.
